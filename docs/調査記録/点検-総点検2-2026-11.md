## 直したもの（中）

- 更新のお知らせの帯が、編集モードの自動判定の通知で置き換わって消え、次の起動まで「更新する」が押せない → 利用者が閉じるまで残すお知らせとして覚えておき、ほかの通知が消えたら出し直す
- 「記法を隠さない表示」（Ctrl+/）を入れて戻すと、箇条書きの記号や自動補完の設定が既定値に戻る → 設定を持つ状態を、モードで入れ替わる側から常設の側へ移した
- Ctrl+B →「太字」→ Ctrl+B →続きを打つと `****` が増える。下線は選択して押すと二重になる → 直後が同じ閉じ記号なら外へ出る。空の組なら外す。下線も外せるようにした
- 記号の自動補完で、`cd ~/.config`・`ls *.txt を実行`・`rm -rf *` の末尾に閉じ記号が残る → 自分で入れた閉じ記号を覚えておき、乗り越えないまま直前で空白を打った・改行した・別の行へ移ったときに取り除く（`pendingCloserField`）
- フロントマターの中の行が、アウトライン・目次・書き出しに見出しとして出る → フロントマターの範囲を飛ばす（`frontmatterEnd`）
- 行の中の `$$E=mc^2$$` で、内側だけが数式になり `$` が残る → `$$...$$` を1つの数式として描く
- 入力やカーソル移動のたびに文書全体の構文木を2回たどっていた（仕様書 8.2）→ 段落内の改行の一覧は設定が "ignore" のときだけ作る。参照定義の収集は構文木ごとに覚え、段落などの中へは降りない
- 空の文書の案内（約650px）が、狭い窓で横のスクロールバーを出す → 折り返して本文の幅に収める（前回の点検で自分が入れたもの）
- 最小の窓でサイドバーを開くと、検索パネルの「閉じる」が窓の外へ出る → 1段目を折り返せるようにした
- 設定のキー割り当てで、元に戻す（Ctrl+Z）・コピー（Ctrl+C）・パレット（Ctrl+Shift+P）など基本のキーと重なっても警告が出ず、一覧には「(なし)」と出る → 基本のキーも重複の検出に数え、一覧にも「基本のキー」として出す
- コマンドパレットで、メニューに出ている名前（「文字を大きく」「リンクを挿入…」）で探せない → メニューで付け替えた名前とサブメニューの名前でも絞り込む
- 設定「バージョン情報」の「自動では通信しません」が、真上の「起動時に確認する」（既定オン）と食い違う → 実際の動きどおりの説明にした
- 取扱説明書・仕様書・README が、お知らせの帯を「画面上部」、「最後のウィンドウを閉じても常駐させる」を「既定でオン」と書いていた → 実際（右下・既定オフ）に合わせた。設定の既定は変えていない
- 復元の確認で Esc や N に手が当たると、未保存の内容がその場で消える → 「はい・いいえ・キャンセル」にし、Esc・×は「キャンセル」（今は開かずに残し、次の起動でまた尋ねる）
- settings.json を同期ソフトなどが開いている瞬間に設定を書くと、既定値で丸ごと上書きされる → 在るのに読めないときは少し待って読み直し、だめなら今回の変更を保存しない
- 関連付けを外すと、その拡張子のキーを丸ごと消し、他のアプリの「プログラムから開く」や Pane の「新規作成」の登録まで消える → 登録の前の既定値を控え、外すときは既定値だけを戻す。キーを消すのは空になったときだけ
- 保存の直後に電源が落ちると、ファイルが空になりうる → 文書と設定は、ディスクまで書き切ってから置き換える（`SettingsService.WriteThrough`）。自動保存は書く回数が多く、本体が残っているので対象にしていない
- 通知領域のメニューの記録に、最近使ったファイルのフルパスが残る → 短くしたパスを書く

## 直していないもの（理由）

- 記号の文字（✓ ▶ など）をSVGへ置き換えること、Calloutのアイコンを5種類に分けること: 見た目が変わるので、案を出して選んでもらう
- 開発者ツールが、既定では選んでも何も起きない: 設定の値を画面側へ渡す配線が要る。次に回す
- Shift_JIS としても読めないファイル（EUC-JP・Latin-1）を警告なしに開く、入れ替えの途中で終了すると exe が欠けうる、たくさんのファイルを一度に開くとプロセスが2つになる、古い置き場所からの設定の再引き継ぎ、サイドバーで開いているファイルの名前を変えたとき、WebView2 の初期化失敗・プロセスの異常終了の扱い: いずれも影響が大きい割に直し方に判断が要る。別に扱う
- 低の39件: 一覧は点検のときの記録にある。大きく困るものは無い

## 繰り返し出てきた誤り

### 測り方の誤り（この点検の途中で見つけた）

`getComputedStyle` で `color-mix()` を使った色を読むと `color(srgb 0.2 0.5 0.6 / 0.28)` という形で返る。これを `rgb(...)` の数字として読むと、0〜1 の値を 0〜255 として扱ってしまい、コントラスト比がでたらめになる。最初の見積もりで「暗いテーマの `--accent-ink` は 1.2〜1.3 で逆効果」「sepia の枠が 15」としたのは、この誤読だった（実測は暗いテーマで 7.6〜8.2、sepia で 4.48）。色の実測は、canvas に塗って画素から読む（`.verify-audit2.mjs` の `toRgb`）。
